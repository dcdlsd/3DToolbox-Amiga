Depannage et securite

OctoControlSpeak ne repond pas

  • Verifier que la pile TCP/IP Amiga est en ligne.
  • Verifier IP, port et cle API OctoPrint.
  • Verifier que OctoPrint est allume.
  • Verifier que l'imprimante est connectee dans OctoPrint.

Liste OctoPrint partielle

Si OctoControlSpeak affiche liste partielle: trop de fichiers, la reponse OctoPrint est trop longue pour la lecture stable sur Amiga.

  • Effacer les anciens G-code dans OctoPrint.
  • Utiliser des noms courts pour les fichiers G-code.
  • Eviter les suffixes tres longs dans les noms de fichiers.

SlicerMUI ne contacte pas le PC

  • Verifier que slicer_server.py tourne sur le PC.
  • Verifier IP et port, par defaut 18090.
  • Verifier le firewall Windows.
  • Verifier ALLOWED_CLIENTS dans slicer_server.cfg.

Client refuse par le serveur

Dans slicer_server.cfg, ajoutez l'adresse IP de l'Amiga: 

ALLOWED_CLIENTS=127.0.0.1,IP_DE_VOTRE_AMIGA

STL trop grand

  • Utiliser STL Info dans SlicerMUI.
  • Lire le scale conseille.
  • Verifier la taille plateau dans le profil PrusaSlicer.

PrusaSlicer ne genere pas le G-code

  • Verifier PRUSA_EXE.
  • Verifier PROFILE_STANDARD.
  • Tester le profil directement dans PrusaSlicer sur PC.

Securite

  • Ne distribuez jamais votre cle API OctoPrint.
  • Ne mettez pas le serveur PC sur Internet.
  • Gardez ALLOW_PC_PATHS=no.
  • Gardez une petite liste ALLOWED_CLIENTS.
  • Testez d'abord de petits objets.
  • Utilisez ZSetupMUI avec prudence.
